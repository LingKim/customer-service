## 一、项目概述

### 1.1 功能范围

上一篇《打造实时通信底座》让客户和客服能聊天了，但只能"一个人接待一个客户"：谁先点开会话谁就负责，客户多了没人知道谁忙谁闲，遇到要转接、要问同事的情况只能靠嘴喊。

这一篇把工作台做成真正能"排班干活"的样子：

1.  **多坐席接待**：工作台分“待接待 / 我的会话 / 全部”三个视角；点“接入会话”才算认领，两人同时抢单只会有一个成功；

2.  **会话协同**：一个会话可以有多个坐席同时在里面（主接 + 协助），头部显示“协助中：某某”；

3.  **内部备注**：客服之间可以在会话里留言，只有坐席看得见，客户既收不到推送、拉历史也被过滤掉；

4.  **转接**：把会话转给其他坐席（带转接说明），或者退回待接待队列；

5.  **会话流转可追溯**：分配、转接、关闭都写 session\_event，能查这条会话经历了什么；

6.  **坐席状态**：谁在线、谁手上几单，实时同步给所有坐席，转接选人时一眼看清；

7.  **结束小结**：结束会话时可以记一句小结，方便质检复盘。

8.  **列表实时刷新**：访客一进来、一发消息，坐席工作台的左侧列表立刻出现，不用手动刷新或重进菜单。

9.  **客户离线自动处理**：客户关掉页面，坐席端马上看到“客户已离线”；离线超过阈值（默认 10 分钟）由系统自动结束会话，待接待列表不会堆一堆僵尸会话。

10. **访客接入安全加固**：访客身份改成服务端签发的令牌（伪造不了）、客户编号随机不可枚举、渠道支持来源域名白名单 + 开会话限流。

### 1.2 新增的接口与协议

HTTP（新增 / 调整）：

|      |                                           |                                                         |
|------|-------------------------------------------|---------------------------------------------------------|
| 方法 | 路径                                      | 说明                                                    |
| GET  | /api/customer/sessions                    | 会话列表，新增 scope：queue-待接待、mine-我的、all-全部 |
| GET  | /api/customer/sessions/{sessionNo}/events | 会话流转记录                                            |
| GET  | /api/customer/internal/sessions/workload  | 各坐席当前接待量                                        |
| GET  | /api/user/members/colleagues              | 同事列表（转接选人，任何企业成员可看）                  |

WebSocket（新增的上行类型，其余沿用上一篇）：

|           |                                        |                          |
|-----------|----------------------------------------|--------------------------|
| 上行 type | 说明                                   | 下行反馈                 |
| CLAIM     | 认领会话（待接待 → 我的）              | SESSION + AGENTS         |
| RELEASE   | 退回待接待队列                         | SESSION + AGENTS         |
| TRANSFER  | 转接给其他坐席（带 toAgentId、remark） | SESSION + AGENTS         |
| NOTE      | 内部备注（只有坐席可见）               | ACK + 仅坐席收到 MESSAGE |

> 一句话区别：JOIN 是“我进来看看”（可多人），CLAIM 才是“这单归我”（只能一人）。

另外新增一个\*\*下行提醒 \*\*`QUEUE`：访客进入排队或发消息时，租户内所有在线坐席都会收到 `{"type":"QUEUE","sessionNo":"...","reason":"VISITOR_ONLINE|VISITOR_MESSAGE"}`。它只报“列表变了”，不搬业务数据，前端收到后按自己的筛选条件重新拉一次列表——这样坐席哪怕没打开这个会话，也能第一时间看到新访客。

访客**上下线**同样走 `QUEUE`，只是多带一个 `visitorOnline` 布尔值（`reason=VISITOR_ONLINE / VISITOR_OFFLINE`），前端不用额外查一次就能把列表状态点、聊天页顶部的“客户在线 / 客户已离线”和离线提示条切过来。坐席连接建立时，`CONNECTED` 还会附一份 `onlineSessions`（当前在线的访客会话号）和 `visitorOfflineCloseMinutes`（自动结束阈值），保证第一帧状态就是准的。

只加一个字段：消息的可见范围。没有新表——会话流转本来就该记在 session\_event 里，那张表在建库时就留好了。

### 文件：schema/customer\_db\_collab.sql

``` code-block-container
-- =============================================================================
-- 在线客服工作台（多坐席接待、转接与会话协同）增量脚本
-- 只加一个字段：消息的可见范围。会话事件直接复用已有的 session_event 表。
-- 可重复执行。

ALTER TABLE "session_message"
    ADD COLUMN IF NOT EXISTS "visible_to" SMALLINT NOT NULL DEFAULT 1;

COMMENT ON COLUMN "session_message"."visible_to" IS '可见范围码：1-客户与坐席都可见、2-仅坐席可见（内部备注）';

-- 老库补约束（已存在时会报重复，用 DO 块兜住，保证脚本可重复执行）
DO $$
BEGIN
    ALTER TABLE "session_message"
        ADD CONSTRAINT ck_session_message_visible_to CHECK ("visible_to" IN (1,2));
EXCEPTION
    WHEN duplicate_object THEN NULL;
END $$;
```

``` code-block-container
package cn.net.susan.customer.entity;

import com.baomidou.mybatisplus.annotation.IdType;
import com.baomidou.mybatisplus.annotation.TableId;
import com.baomidou.mybatisplus.annotation.TableName;
import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Data;
import lombok.NoArgsConstructor;

import java.time.LocalDateTime;

/**
 * session_event 会话事件表：转接、升级、分配、关闭、超时都能追溯。
 */
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
@TableName("session_event")
public class SessionEvent {

    @TableId(value = "id", type = IdType.INPUT)
    private Long id;

    private String tenantCode;

    private Long sessionId;

    /** 事件类型码：1-转接、2-升级、3-分配、4-关闭、5-超时 */
    private Integer eventType;

    /** 操作人（坐席用户 ID） */
    private Long operatorId;

    /** 来源值（原坐席 / 原技能组） */
    private String fromValue;

    /** 目标值（新坐席 / 技能组 / QUEUE 表示退回队列） */
    private String toValue;

    /** 备注（转接原因、结束小结等） */
    private String remark;

    private LocalDateTime eventTime;

    private LocalDateTime createTime;
}
```

### 文件：yunti-backend/yunti-customer-service/src/main/resources/mapper/SessionEventMapper.xml

这个文件不是第 12 / 15 篇建的，直接给整份内容，照着整文件覆盖：

``` code-block-container
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="cn.net.susan.customer.mapper.SessionEventMapper">

    <!-- 会话流转记录 -->
    <select id="selectBySession" resultType="java.util.Map">
        SELECT e.id,
               e.event_type  AS event_type,
               e.operator_id AS operator_id,
               e.from_value  AS from_value,
               e.to_value    AS to_value,
               e.remark      AS remark,
               e.event_time  AS event_time
          FROM session_event e
         WHERE e.tenant_code = #{tenantCode}
           AND e.session_id = #{sessionId}
         ORDER BY e.event_time DESC, e.id DESC
         LIMIT #{limit}
    </select>
    <!-- 坐席当前接待量：只统计"人工接待中"的会话 -->
    <select id="selectAgentWorkload" resultType="java.util.Map">
        SELECT s.agent_id       AS agent_id,
               COUNT(1)         AS session_count
          FROM session s
         WHERE s.tenant_code = #{tenantCode}
           AND s.agent_id IS NOT NULL
           AND s.status = 3
           AND s.is_deleted = FALSE
         GROUP BY s.agent_id
    </select>
</mapper>
```
