<div class="ql-code-block">

## 八、访客接入安全加固

  

前面几节的访客接入是"能用"版本，但有两个必须补上的安全短板，这一节顺手修掉（也正因为要改这几个文件，工作台这一篇的代码才和仓库完全一致）：

1.  <span class="ql-ui"></span>**匿名访客身份可伪造**：原来是前端存明文客户编号、服务端只查表不校验，编号又是"V + 时间戳 + 3 位随机"，猜到或拿到就能顶替别人。改成服务端签发**访客身份令牌**（typ=3，默认 30 天），客户编号换成 130 位随机串；

### 总结

  

这一篇把“能聊天”做成了“能一起干活”：

1.  <span class="ql-ui"></span>**责任边界清楚**：JOIN 只订阅，CLAIM 才认领，一人一单但可多人协助；
2.  <span class="ql-ui"></span>**并发交给数据库**：抢单冲突不靠分布式锁，靠“库里已有负责人就拒绝”，简单可靠；
3.  <span class="ql-ui"></span>**协同不打扰客户**：内部备注走可见范围字段，推送和查历史两处都拦；
4.  <span class="ql-ui"></span>**流转可追溯**：分配、转接、关闭全部落成会话事件，质检和复盘都有据可查；
5.  <span class="ql-ui"></span>**状态不落库**：坐席在线看连接、接待量看会话统计，少一张表少一份维护成本；
6.  <span class="ql-ui"></span>**列表靠信号刷新**：会话内消息仍只推给“正在看这个会话”的人，列表变化另走一条 QUEUE 轻量提醒，前端合并 300ms 再拉一次，既不漏消息也不把接口打爆。
7.  <span class="ql-ui"></span>**离线即收口**：访客断开长连接就标记离线并通知坐席，超过阈值自动结束会话——规则明确、可配置（YUNTI\_VISITOR\_OFFLINE\_CLOSE\_MINUTES=0 可关掉），待接待列表始终干净。
8.  <span class="ql-ui"></span>**安全不留口子**：访客身份由服务端签发令牌、客户编号不可枚举、渠道限来源域名并限流——公开的 appKey 不再是"谁拿到谁就能用"的入口。
